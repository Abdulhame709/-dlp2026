## 3. إجابات الأسئلة البنيوية والتفصيلية (Architectural Q&A)

### أين يتم تعريف `DATABASE_URL`؟
* **مكان التعريف:** يتم تعريفه في متغيرات البيئة الحاضنة للتطبيق (Environment Variables) مثل لوحة تحكم **Vercel** أو ملف البيئة المحلي `.env.local`.
* **مكان الاستهلاك:** يتم استهلاكه داخل ملف المخطط `prisma/schema.prisma` عبر السطر التالي:
  ```prisma
  datasource db {
    provider = "postgresql"
    url      = env("DATABASE_URL")
  }
  ```
* **الاستخدام الفعلي:** يُستخدم حصرياً بواسطة **Prisma CLI** لتنفيذ عمليات الهجرة وهيكلة الجداول وسحب المخطط من وإلى السحاب السحابي (`npx prisma migrate deploy` أو `npx prisma db seed`). ولا يتم قراءته مباشرة داخل الكود التشغيلي للتطبيق (Next.js Edge Runtime) مما يعزز الأمان والسرعة وخفة الحزم.

---

### أين يتم تعريف `DIRECT_URL`؟
* **مكان التعريف:** **غير معرف حالياً** في الكود التشغيلي أو ملفات الإعدادات.
* **السبب والتحليل:** المنصة تعتمد بالكامل على رابط واحد هو `DATABASE_URL` الموجه نحو مجمع الاتصالات التبادلي (Transaction Pooler) الخاص بـ Supabase عبر منفذ `6543` مع إلحاق معامل الاستقرار البيني `?pgbouncer=true`.
* **توصية هندسية (SRE Best Practice):** ينصح بشدة بإضافة `DIRECT_URL` في ملف `prisma/schema.prisma` لتجنب أية مشكلات اتصال أو قيود أثناء تنفيذ الهجرات الكبيرة التي تتطلب اتصالات DDL مباشرة (منفذ `5432` دون المرور بـ PgBouncer):
  ```prisma
  datasource db {
    provider  = "postgresql"
    url       = env("DATABASE_URL")
    directUrl = env("DIRECT_URL")
  }
  ```

---

### كيف يتم اختيار `USE_MOCK`؟
* **آلية القراءة:** يتم قراءة وتعيين هذا الخيار داخل ملف `src/core/config/env.ts` عبر التحقق التالي:
  ```typescript
  useMock: process.env.USE_MOCK !== 'false'
  ```
* **قاعدة التفعيل والتحول:**
  * **الوضع الافتراضي (Default):** إذا لم يتم تعريف المتغير `USE_MOCK` أو إذا تم تركه فارغاً، أو تم ضبطه على `true`، فإن التطبيق **يعود تلقائياً** وبأمان إلى وضع الـ **Mock** لمنع أي توقف للمطورين محلياً أو فشل الاتصال بقواعد البيانات الخارجية.
  * **الوضع السحابي الحي (Live Mode):** يتحول التطبيق بالكامل إلى الاتصال الحي فقط عندما يتم وضع القيمة المباشرة والصريحة التالية: **`USE_MOCK=false`**.
* **آلية التنفيذ البرمجي:** يعتمد محقن الاعتماديات `DependencyInjector` على هذا العلم لتنفيذ عملية استيراد ديناميكية (Dynamic Import) لوحدات التخزين الحية مثل `SupabaseTaskRepository` وتصديرها لواجهة التطبيق بشكل معزول تماماً عن كتل الـ Client Components.

---

### هل يستخدم المشروع فعلياً Prisma أم Supabase Client أم الاثنين معاً؟
يستخدم المشروع **الاثنين معاً، ولكن بأدوار هندسية منفصلة ومعزولة تماماً (Strict Separation of Concerns):**

1. **مستودع البيانات السحابي والتخاطب الحي (Supabase Client):**
   * هو المحرك الفعلي للتطبيق في بيئة الإنتاج والتشغيل الفعلي (Next.js Runtime / Edge Endpoints).
   * تقوم مستودعات الخدمات في المسار `src/features/.../supabase-...-repository.ts` بالاستعلام المباشر من جداول PostgreSQL السحابية عن طريق حزمة `@supabase/ssr` دون الاستعانة بـ Prisma Client.
   * **الفائدة:** يضمن ذلك سرعة استجابة مذهلة تحت حاجز 50 جزء من الثانية، والعمل بآمان تام داخل خوادم Edge Serverless دون مواجهة مشكلات محركات Prisma الثقيلة أو استهلاك الذاكرة.

2. **هيكلة وإدارة قاعدة البيانات والهجرات (Prisma ORM):**
   * يستخدم Prisma **حصرياً كأداة تطوير وتصميم وصيانة**.
   * هو المسؤول عن ترجمة المخططات البرمجية إلى جداول وقواعد حقيقية وتصدير الهجرات الهيكلية (Migrations) إلى خادم PostgreSQL في Supabase.
   * **الفائدة:** يعطي المطورين تحكماً كاملاً وصارماً في تتبع تغيرات قاعدة البيانات عبر نظام Git مع توفير كتابة أكواد اختبارية سهلة وبثقة عالية قبل النشر الفعلي.

---

### ما الملفات التي تحتاج فقط Environment Variables بدون تعديل كود؟
المنصة مصممة برمجياً للعمل بشكل متكامل وديناميكي بمجرد حقن متغيرات البيئة الصحيحة. **لا يحتاج أي كود برمجي إلى التعديل** لإتمام عملية الاتصال الحي.

الملفات التي ستستقبل هذه المتغيرات تلقائياً هي:
1. `src/core/config/env.ts` (يقوم بنشر المتغيرات السحابية لكامل خلايا التطبيق).
2. `prisma/schema.prisma` (يستقبل رابط قاعدة البيانات لبدء ترحيل الهجرات).
3. `src/core/config/config-manager.ts` (يتأكد تلقائياً من صحة ووجود المفاتيح ويعلن للمشروع انتفاء وضع المحاكاة).

المفاتيح الستة (6) الحرجة والواجب حقنها في البيئة السحابية الحاضنة (مثل Vercel) هي:
```bash
# 1. مفاتيح الاتصال الحي بـ Supabase (تُحضر من Settings -> API)
NEXT_PUBLIC_SUPABASE_URL="https://your-project-id.supabase.co"
NEXT_PUBLIC_SUPABASE_ANON_KEY="eyJhbGciOi..."
SUPABASE_SERVICE_ROLE_KEY="eyJhbGciOi..." # مفتاح المشرف لعمليات التحقق والتدقيق الآمنة

# 2. رابط قاعدة البيانات لتمرير الجداول والهجرات (تُحضر من Settings -> Database)
DATABASE_URL="postgresql://postgres.your-project-id:your-db-password@aws-0-us-east-1.pooler.supabase.com:6543/postgres?pgbouncer=true"

# 3. مفتاح الذكاء الاصطناعي الفعلي لتفعيل المساعد الذكي وصانع الأهداف
OPENAI_API_KEY="sk-proj-..."

# 4. تعطيل وضع المحاكاة والتحول للبث السحابي الحي والآمن فوراً
USE_MOCK="false"
```

## 5. دليل خطوات النشر والربط السحابي الفعلي (Step-by-Step Deployment Runbook)

للانتقال الآمن إلى السحاب وضمان استمرارية الخدمات دون توقف، اتبع الخطوات الترتيبية التالية:

### الخطوة 1: إنشاء مشروع Supabase وتجهيز قاعدة البيانات
1. قم بإنشاء مشروع جديد عبر لوحة تحكم [Supabase](https://supabase.com).
2. احفظ كلمة مرور قاعدة البيانات (Database Password) في خزنتك بأمان.
3. توجه إلى **Settings ➔ Database** وقم بنسخ رابط الاتصال بالصيغة **URI** مع التأكد من تحديد خيار **Transaction Pooler** (منفذ `6543` ومتبوعاً بـ `?pgbouncer=true`).

### الخطوة 2: تهيئة وتصدير جداول قاعدة البيانات (Database Schema Deployment)
من خلال سطر الأوامر في المستودع الفعلي، قم بتصدير المخطط عبر Prisma بالتعريف التالي:
```bash
export DATABASE_URL="postgresql://postgres.your-project-id:your-db-password@aws-0-us-east-1.pooler.supabase.com:6543/postgres?pgbouncer=true"
npx prisma migrate deploy
```
*معيار التحقق:* توجه إلى لوحة تحكم Supabase قسم **Table Editor** وتأكد من ظهور كافة الجداول المعتمدة (مثل `profiles`, `tasks`, `goals`, `organizations`, `projects`).

### الخطوة 3: تجهيز مستودع الملفات والقنوات الحية
1. **إنشاء الحاوية الخاصة بالملفات:** توجه لقسم **Storage** في Supabase وأنشئ حاوية خاصة جديدة باسم **`attachments`** وقم بضبطها على وضع الخصوصية المغلق (**Private**).
2. **تفعيل قنوات البث الفوري (Realtime):** توجه إلى **Database ➔ Replication** وقم بتفعيل قنوات البث المباشر للجداول التالية: `tasks` و `notifications` و `ai_conversations`.

### الخطوة 4: ربط المستودع في منصة Vercel وحقن المفاتيح الآمنة
1. سجل الدخول إلى [Vercel](https://vercel.com) واستورد مستودع المشروع الحالي.
2. اختر الفرع النشط والمستقر الحالي: **`arena/019fa52b-dlp2026`**.
3. قم بفتح نافذة المتغيرات البيئية (Environment Variables) وقم بإدراج المفاتيح الستة المذكورة أعلاه في هذا التقرير مع إسناد القيمة **`USE_MOCK=false`**.
4. اضغط على زر **Deploy**. سيقوم محرك Vercel ببناء وتجميع التطبيق (Next.js 15 + Turbopack) ورفعه حياً خلال دقيقة واحدة!

### الخطوة 5: التحقق من استقرار بيئة الإنتاج المباشرة
بعد نجاح البناء والرفع السحابي، قم بتشغيل الفحص السحابي الشامل والمباشر من جهازك للتأكد من استقرار كافة نقاط النهاية ومصادقة المستخدمين ومستودعات التخزين:
