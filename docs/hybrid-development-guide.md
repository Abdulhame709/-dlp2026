## 🎯 1. فلسفة هندسة التطوير الهجين (Adaptive Hybrid Strategy)

تم تصميم وتجهيز مشروع **Cortex AI** ليعمل بمرونة تشغيلية مطلقة تدعم مساري عمل منفصلين ومتكاملين (Dual-Mode Execution) دون الحاجة لإجراء أي تغيير بنيوي أو إعادة هيكلة للكود البرمجي (Zero Architectural Refactoring). يضمن هذا التصميم ثبات خط الإنتاج السحابي وحماية بيئة المطورين المحليين من الانهيار.

---

## ⚙️ 2. أنماط التشغيل المدعومة (Dual Execution Modes)

### النمط الأول (الأساسي): التطوير السحابي المتكامل (Cloud Development)
هو المسار القياسي والمعتمد لإطلاق وإدارة أصول المنصة حية للإنتاج والنسخ التجريبية.
* **آلية التدفق:**  
  `LM Arena ➔ GitHub ➔ Auto Vercel Build ➔ Supabase Cloud`
* **متى يُستخدم؟** عند ترحيل التعديلات النهائية، تجميع الأصول الحية، وتخديم المستخدمين الفعليين بالاعتماد على قاعدة بيانات Supabase وقنوات البث اللحظي (Realtime) وبوابات OpenAI الحقيقية.
* **طريقة التفعيل:** وضع العلم المالي والتشغيلي صراحة: **`USE_MOCK=false`** في متغيرات البيئة لـ Vercel.

### النمط الثاني (الاحتياطي): التطوير والاستكشاف المحلي (Local Debugging Fallback)
هو خط الدفاع الثاني المخصص لمجالات الصيانة والتحقق المحلي السريع واستكشاف الأخطاء ومعالجتها (Offline Debugging).
* **آلية التدفق:**  
  `Developer ➔ VS Code ➔ npm install ➔ local debugging`
* **متى يُستخدم؟** في حالات غياب الإنترنت، أو عدم توفر مفاتيح السحاب، أو الحاجة لاختبار الميزات محلياً ومعالجة الأكواد بآمان مطلق دون المساس ببيئة الإنتاج السحابية.
* **طريقة التفعيل:** الحفاظ على القيمة الافتراضية: **`USE_MOCK=true`** (يقوم التطبيق بالعمل ذاتياً بالاعتماد على الماكتيات الوهمية عالية الدقة لـ IndexedDB وقواعد البيانات المحلية المتكاملة).

## 🛠️ 3. أدوات التحقق التلقائي والتهيئة (Automated Bootstrap & Checkers)

لتبسيط عمل المطورين وتفادي التعقيدات اليدوية، تم تصميم أداتين ذكيتين للمراقبة والتهيئة:

### أ. أداة تهيئة المستودع الفورية (`scripts/bootstrap.js`):
عند تفعيل مستودع جديد أو سحبه لأول مرة، يكتفي المطور بتشغيل سطر واحد فقط من جذر المشروع:
```bash
node scripts/bootstrap.js
```
تقوم الأداة آلياً بالمهام التالية:
1. فحص وتثبيت حزم الـ `node_modules` المتطابقة.
2. تجميع وتوليد كلاسات الـ `Prisma Client` لضمان توافق الفئات.
3. قراءة وفحص حالة الـ `USE_MOCK` لتحديد النمط النشط.
4. في حال التوصيل الحي للإنتاج (`USE_MOCK=false`): تقوم بتمرير ترحيل الجداول سحابياً صامتاً (`migrate deploy`) وتهيئة الخصائص التشغيلية عبر سكريبت التأسيس `production-seed.ts`.

### ب. مدقق متغيرات البداية ومراقبة الـ Health Endpoint:
* **مدقق الطرفية التلقائي (`ConfigManager`):** عند تشغيل خادم التطوير عبر `npm run dev`، يقوم النظام تلقائياً بمسح مفاتيح (`NEXT_PUBLIC_SUPABASE_URL`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `DATABASE_URL`, `DIRECT_URL`). في حال غيابها أو استخدام ماكيتات، يصدر النظام تنبيهاً SRE ذكياً وواضحاً في الشاشة يوجه المطور لكيفية التغذية السليمة ويعلمه بأن وضع الأمان للمحاكي نشط لتلافي انهيار تشغيل الموقع.
* **نقطة التحقق البرمجية (`/api/v1/health`):** مسار مخصص لاستقبال فحوصات المراقبة الفورية (Datadog/Pingdom) يعيد بيانات مبرمجة بصيغة JSON توضح أمان واستقرار الاتصالات السحابية بالكامل، وتفادي الفحوصات الخارجية في حال تفعيل الماكيتات لضمان دقة الرصد الميداني.

## 🚀 4. دليل النشر الآمن وتحديث الجداول (Zero-Downtime Migration Playbook)

لتمرير أي تعديلات سحابية أو تحديث الجداول دون التأثير على استمرارية الخدمة للعملاء، اتبع البروتوكول الصارم التالي:

### الخطوة 1: الفحص والتدقيق المحلي المسبق
قبل إطلاق أي ترحيل هيكلي لقواعد البيانات، تأكد من استقرارية الكود وخلوه تماماً من أخطاء التنسيق بتشغيل تدقيق الجودة والاختبارات محلياً:
```bash
npm run lint
npm run test:db
```

### الخطوة 2: تهيئة المتغيرات السرية في المستودع
تأكد من إدراج المتغيرات الحقيقية لـ `DATABASE_URL` و `DIRECT_URL` داخل إعدادات **GitHub Secrets** الخاصة بمستودعك كما هو موضح في دليل CI/CD.

### الخطوة 3: تمرير الترحيل الصامت لـ Supabase (Silent Database Migration)
* لا تقم بتشغيل أوامر الـ Reset أو `migrate dev` للإنتاج نهائياً لتلافي حذف أي بيانات للعملاء.
* توجه لـ **GitHub Actions**، اختر سير العمل **`Manual Database Schema Migration`** واكتب قيمة التأكيد **`DEPLOY`** للبدء.
* سيقوم الخادم بتطبيق الترحيل بأمان تام عبر المنفذ المباشر المخصص `DIRECT_URL`.

### الخطوة 4: تهيئة الخصائص (System Configurations Seeding)
لتنصيب وتغذية جداول الميزات (Feature Flags) ببيانات النظام الأساسية دون المساس ببيانات الحسابات الشخصية، شغل سكريبت التأسيس الآمن من جهازك أو عبر سياقات الـ Actions:
```bash
npx tsx prisma/production-seed.ts
```

### الخطوة 5: التحقق من نجاح الاتصال وصحة نقطة النهاية (Live Verification)
افتح المتصفح وتوجه لنقطة النهاية المباشرة المخصصة للتحقق من الصحة والاتصال في لوحتك الحية:
📍 **`https://your-vercel-domain.com/api/v1/health`**
تأكد من عودة الاستجابة بالقيمة الاستقرارية التامة: `{"status": "healthy", "api": "available", "database": "connected"}` لضمان استقرار كامل خدمات المنصة.
